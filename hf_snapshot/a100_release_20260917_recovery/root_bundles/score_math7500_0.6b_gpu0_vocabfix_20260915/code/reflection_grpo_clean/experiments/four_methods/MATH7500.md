## 数据和固定条件

本地 `math7500.parquet` 原始 7,500 行，隔离 2 条空答案、去掉 1 条重复题，排除
1 条人工确认的 MATH500 重合题，保留 **7,496 题**。排除清单位于 `data/excluded.jsonl`。
第 304 行与 MATH500 的 `test/algebra/170.json` 是同一道不等式计数题，仅措辞不同。
原文件不修改，源文件 SHA256 固定在配置中。相似题检查不是穷尽的语义去重。

四种方法使用同一组题目、答案和随机顺序；只按方法构造 prompt。
GRPO/PAG/SCoRe 从原 Base 开始，REFLECT+ 从原 phase2 checkpoint-268 合并模型开始。
复用并校验上轮已经验证的合并模型及其 SHA256，避免改变 REFLECT+ 初始化。
此次重新做 CPU 合并未通过 logits 一致性检查，失败产物没有投入使用；
复用记录和原失败日志保存在 `preparation/initialization_reuse.json`、`prepare_attempt1.log`。

依旧为 500 步，64 题/步、8 条轨迹/题，双 GPU 0、1，禁止 thinking。
Actor lr=1e-6，critic lr=2e-6；其余算法参数沿用 DAPO 对照配置。
每 50 步及训练前，在 MATH500 500 题 + AMC23 40 题上验证 pass@4、mean@4，
temperature=0.7、top_p=0.8、top_k=20。训练 temperature=1.0。
验证每批128题，一次完整验证分5批；训练批量、验证题目数和采样次数保持原约定。

## 训练和验证的生成长度

**当前三个baseline按每次完整解题4096 tokens对齐，PAG验证2048；不再强制轨迹总预算相等。**
训练、MATH500验证、AMC23验证均使用下表；生成长度不含输入题目及程序插入的反馈。

| 方法 | 各阶段生成上限 | 总上限 |
|---|---|---|
| GRPO | 解题 4096 | 4096 |
| REFLECT+（独立配置） | 首轮 4096 + 反思触发续写 4096 | 8192 |
| PAG | 解题 4096 + 验证 2048 + 条件重解 4096 | 10240 |
| SCoRe | 首轮 4096 + 第二轮 4096 | 8192 |

各阶段未用完的额度不转移，PAG 验证文本也计入生成成本。
`max_prompt_length=2048`，`max_model_len=16384`，为历史回答及反馈留出空间。
REFLECT+暂不运行；baseline配置内的旧占位字段仍为2048+2048，后续REFLECT使用独立入口。
比较结果时同时报告实际生成token和时间成本。
本次长度变更使原GPU预检失效，正式启动前需重新预检；CPU轨迹测试不代替长上下文显存检查。
最长已准备训练 prompt 为 1727 tokens，题目不截断。是否需要提高各阶段额度应根据
正式采样的截断率判断；现有少量测速/预检采样不足以代表完整训练分布。

vLLM 每卡 `max_num_seqs=32`，`gpu_memory_utilization=0.50`，
`max_num_batched_tokens=8192`，`enforce_eager=false`，开启 CUDA Graph。
训练仍按每卡16384 tokens动态组批，保留梯度检查点、BF16及TP=1的双采样副本。
两张卡分别对比原来的16并发/eager和新配置，同一组题各64条独立回答，
采样吞吐从约315升到1279 tokens/s（约4.1倍）。新配置的64条×4096 tokens
长输出压力测试完成且没有KV重算。具体范围和局限见 [THROUGHPUT.md](THROUGHPUT.md)。

## 新评分规则

新配置显式选择 `fourway-math-v5-20260914`；未指定版本的旧实验仍走 paired-v4。
四个方法的训练 outcome 判分和验证共用 `fourway/scoring.py`，符号比较使用
`fourway/math_scoring.py`。PAG 验证奖励、SCoRe shaping、REFLECT+ 反思奖励仍属于
各自算法；它们不会替代验证时的最终答案正确率。

- 只提取最终完整 boxed/fbox 或明确 Answer 行，不在推理中随意搜数字。
  反思中引用的错误答案不计分；最终 box 未闭合时不回退到之前的答案。
- 不按训练/验证数据集名称切换整数容差。可直接解析的整数标签采用精确比较；
  简单分数用有理数比较。非整数答案的十进制近似使用绝对 1e-8 容差，
  不使用会随答案变大而放宽的相对容差。
- 百分数转换为数值，50% 等于 0.5，不等于 50；保留坐标顺序、矩阵结构、
  集合完整性和区间端点。进制、选择项、文字答案、时刻单独处理。
- 明确列出的单位后缀可省略；不使用会把代数变量 c、t 当单位删除的宽泛规则。
  标准答案的百分数、句尾标点、排版空格和分数写法按相同规则规范化。
- 缓存解析结果；简单数字和分数优先快速比较，复杂答案才进入符号比较。
- 缺失/不完整答案、已识别的语法错误记 0 并标明状态。超时、未知解析器错误或
  工作进程故障重试后仍失败则记录完整输入到 `diagnostics/reward_errors/` 并停止，
  不静默伪装为答错。

`preflight` 对所有保留的训练/验证标准答案做解析和最终答案提取检查，记录代码及
数据指纹；这能检查兼容性，不能证明数据源中每道题的标准答案本身都正确。
Math-Verify 的比较接口及 gold-first 顺序参考其[官方说明](https://github.com/huggingface/Math-Verify)。

## 操作与证据

```bash
cd /root/reflection_grpo_clean
bash experiments/four_methods/run_math7500.sh prepare
bash experiments/four_methods/run_math7500.sh preflight
bash experiments/four_methods/run_math7500.sh dry-run
```

以上操作不启动模型训练。修改配置后，启动前需要通过对应配置的 GPU 预检，旧配置的结果不能复用：

```bash
bash experiments/four_methods/run_math7500.sh preflight --gpu --method grpo
bash experiments/four_methods/run_math7500.sh preflight --gpu --method pag
bash experiments/four_methods/run_math7500.sh preflight --gpu --method score
```

只有用户要求开始后再执行正式训练/顺序队列，并从各自初始模型开始；不续接 DAPO 第100步。
当前用户已授权依次启动三个baseline。对应队列命令如下（须先通过当前配置的三个方法GPU预检）：

```bash
/home/vipuser/miniconda3/envs/wrx_env/bin/python -u -m fourway.queue \
  --config experiments/four_methods/config.math7500.json --methods grpo pag score
```

正式启动使用脱离终端的独立会话，stdin关闭，总日志写入`queue/queue.log`，
PID写入`queue/pid`，状态写入`queue/status.json`。队列不会执行REFLECT+，
各方法完成后检查500步latest和best checkpoint，再自动进入下一个方法；任何失败停止队列。
准备记录见 `preparation/{cpu_tests.log,math_label_audit.json,cpu_preflight.json,replay_step100.json}`。
`replay_step100.json` 是对旧实验保存的 2160 条回答的离线评分复查，原始结果不覆盖。
`scoring_microbenchmark.json` 只测 CPU 判分中的 512 个简单数值例子，不代表端到端训练速度。
