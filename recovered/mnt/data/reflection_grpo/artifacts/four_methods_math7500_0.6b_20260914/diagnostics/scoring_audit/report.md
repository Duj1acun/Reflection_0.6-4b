判题运行时检查与修复，2026-09-14。

检查范围：当前 fourway-math-v5 判题器、独立 CPU 判题进程、两个原生 verl 训练循环、训练期间验证及检查点保存。未启动 GPU 训练。

已复现并处理的问题：

- 巨大整数幂：此前的模运算修复能判别部分错误答案，但正确的 `2^(2^2008) / 2^(2^2008) = 1` 仍会超时。现在可用形式符号证明相同巨大幂的消去，避免展开整数。无法证明的表达式仍保留为判题失败。
- Math-Verify 的 `TimeoutException` 直接继承 `BaseException`，原来的 `except Exception` 捕获不到。现在在评分函数和进程调用处均明确捕获该超时，不吞掉 KeyboardInterrupt/SystemExit。
- 答案提取原先位于超时与异常保护之外，现在纳入保护；答案长度检查提前到归一化之前。
- 不规则矩阵、矩阵维数不匹配、非方阵行列式及未定义对数可能抛出异常。明确的输入格式/定义域错误归类为无效答案；未知错误仍报告失败。错误的标准答案不再被归类为模型答错。
- reward 外层会在判题器已重试失败后重放整个批次。当前 fourway 路径取消了这个重复执行。
- 判题子进程原先只有 terminate，没有确保退出。现在使用有界等待和 kill 后备，并限制独立 CPU 子进程额外虚拟地址空间至 512 MiB；解析缓存从 8192 缩小为 1024。
- 分数语义：补齐 `\frac12` 的精确数值路径，使近似容差与 `\frac{1}{2}` 一致；AM/PM 时间统一转换到 24 小时格式。

按用户选择启用的训练策略：

- 配置文件：`/root/reflection_grpo_clean/experiments/four_methods/config.math7500.json`。
- `judge_failure_policy = "skip_batch"`，`judge_max_consecutive_failures = 3`。
- 单条判题仍最多尝试两次，每次父进程等待上限为 15 秒；内部评分通常有 8 秒保护。
- 无法判定时跳过整个训练批次，记录题目 ID、当前步数、原因和 traceback，不更新 actor/critic，不增加成功训练步数。成功判题后重置连续失败计数；连续三个批次判题失败则停止。
- 只处理明确的 JudgeError 及其本地/Ray 包装。模型、CUDA、通信等其他错误以及参数更新开始后的异常不会被伪装成可跳过批次。
- 训练期间验证失败时记录 `.failed.json`，不发布准确率，不参与 best 选择；训练检查点仍可保存。验证失败连续计数独立于训练批次计数，连续三次验证失败停止。显式 evaluate/val_only 保持严格失败。
- 跳过累计数及失败计数写入检查点并随恢复加载。
- GRPO/Reflection 与 PAG/SCoRe 的两个原生训练循环均已接入。其他未启用上述配置的实验仍保持严格策略。
