# Teacher v1 小样本实调用质量复核

结论：接口可用且返回了 thinking，但当前 v1 不应直接放大为批量 SFT 标注。4 条候选没有形成可直接收录的完整反思—续推记录；问题不仅是格式，还包括错误定位、状态来源、答案泄漏和数学错误。

- 请求与响应模型均为 MiniMax-M2.7。

- Perfect API 请求为 0。没有启动整批标注或 SFT，也没有修改原始判分标签。
- API key 经隐藏终端输入，仅在调用进程内使用。未放入参数、配置、请求留档或报告；本次产物的凭据模式检查未发现匹配。

## 具体证据

### 0.6B：糖果题

Teacher 正确定位到原回答 S0013 中把后续被擦除的数字也都视为 1 的假设。

但 new_direction 声称反复选择最小的两个数会形成 1,2,3,...,26 的序列，这混淆了“总选最小两个数”与“一个累积和不断加 1”的策略。以 4 个 1 为例，选择最小两个数产生的新数为 2、2、4，不是 2、3、4。

真正的数学关系是：合并 a、b 时，平方和增加 2ab。总和保持 26，最终仅剩 26；累计糖果为 (26^2-26)/2=325，和具体合并顺序无关。26 个数最多做 25 次合并，第 26 分钟已无可合并的数。

续推使用上述平方和论证得到 325，数学主线正确，但直接更换了反思给出的方向并返回 status=ok，没有指出反思的矛盾。此外它没有输出 boxed 答案，且存在过度转义的换行和 LaTeX 命令。

这条还显示 verified_states 的来源约束没有完全落实：总和守恒、数量每次减少 1 虽然正确，但没有作为原回答错误前已经建立的结论出现。需要区分题目已知条件、学生已有结论和 teacher 新推得的结论。

### 0.6B：固定点题

Teacher 给出的 first_error_quote 将原文的弯引号、Markdown 和 LaTeX 改成了普通文本，不再是 S0026 的逐字子串。

它识别出任意设 A=(1,log_a(4)) 没有依据，这一诊断有价值。但更早的 S0015/S0017 已把带有 -8/9 的函数曲线误换成了没有平移项的曲线。

正确路线是利用 log_a(1)=0 得到 A=(-2,-8/9)，进而 b=-1，最终 f(log_3 2)=1。Teacher 提出的固定点路线是合理的，但没有产生续推调用；不能将预期答案记成 API 续推成功。

### 4B：系数和题

首次错误推断位于 S0013：把对 x 的取值 x=1 当成对新基底 x+2 取值 1。

Teacher 却定位到 S0019 的数值等式；这个等式本身运算正确，只是求了不需要的 x=1 处函数值。错误类型 domain_constraint 也不准确，更接近基底/变量理解错误。

new_direction 不仅给出 x=-1，还直接算出了最终答案 -2。这违反反思不提前给最终答案的约定，导致第二次请求虽然没有单独传 reference_answer，仍通过 reflection_text 得到了答案。

续推的计算结果 -2 正确，但缺少 boxed 格式，而且不能据这条证明续推依赖有效反思获得了增益。

### 4B：分式化简题

原回答定义 a=p/q、b=q/p，因此 ab=1。它最终的表达式为：

    ((a^2-1)(a+b-1)) / ((a-b)(a^2-a+1))

代入 b=1/a，在原式有定义的范围内该式化简为 1。不能把“未化简到最终常数”直接标注成前面某个等价变形算错。

Teacher 却声称：

    a^2-1 = (a-b)(a+b)

这是错误恒等式。取 a=2、b=1/2，左边为 3，右边为 15/4。它进一步把这个错误关系作为 new_direction 的核心，并要求验证等于参考答案 1。

该条 thinking 字段有 22,018 个字符，仍然产生上述错误；开启 thinking 本身不能代替质量审核。

## 下一步建议（尚未实施或调用）

1. 必须单独处理“等价但未化简完成”，不能为了找错误而编造错误变形。
2. 可试验让诊断先不看参考答案，减少向 gold 靠拢的压力；这是待验证的改进假设，不是已经证实的修复。
3. 错误引用可由程序根据 teacher 选定的段落 ID 提取，降低逐字复制失败；但这不能解决错误步骤选晚的问题。
4. 让有效状态附带来源定位，并明确分开已有状态与新修正结论；通过示例和语义审核检查答案泄漏。
5. 续推可增加独立 final_answer 字段，由程序统一生成 boxed 格式，并检查它与推导结论一致。不能仅给本次结果补框，因为上游反思仍有语义问题。
6. 修订后先对相同题目复测，再扩大抽样。不要根据这 4 条推断整批合格率，也不能断言温度 0.3 是问题的原因。

## 原始留档

- samples.json：原始学生回答与分段定位。
- manifest.json：冻结的 v1 prompt、schema、采样来源和准备配置。
- run_config.json：实际 endpoint、参数、运行时间与执行脚本哈希。
- calls/*.request.json：不含 Authorization 的请求体。
- calls/*.response.json：原始响应，包含独立 thinking 字段与最终 content；不是 SFT 成品。
- calls/*.result.json、results.json、summary.json：程序校验与执行结果。

本报告没有改写 teacher 的原始响应，也没有把人工修正伪装成 API 输出。
